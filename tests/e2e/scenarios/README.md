# E2E 테스트 시나리오 문서

## 개요

이 디렉토리는 캘린더 일정 관리 애플리케이션의 E2E 테스트 시나리오 문서를 포함합니다. 각 시나리오는 실제 사용자 워크플로우를 기반으로 작성되었으며, Playwright 등의 E2E 테스트 도구로 자동화할 수 있도록 상세한 단계를 제공합니다.

## 테스트 환경

### 필수 조건

- **애플리케이션 URL**: http://localhost:5173 (Vite dev server)
- **백엔드 API**: http://localhost:3000 (Express server)
- **테스트 환경 변수**: `TEST_ENV=e2e`
  - 이 환경 변수 설정 시 `src/__mocks__/response/e2e.json` 파일을 사용
- **브라우저**: Chromium, Firefox, WebKit (Playwright 지원 브라우저)

### 환경 설정

```bash
# 1. 백엔드 서버 시작 (E2E 테스트 모드)
TEST_ENV=e2e pnpm server

# 2. 프론트엔드 개발 서버 시작 (다른 터미널)
pnpm start

# 3. E2E 테스트 실행
# (Playwright를 사용하는 경우)
npx playwright test
```

### 1. 기본 일정 관리 (01-basic-event-management.md)

**우선순위**: Critical
**예상 실행 시간**: 2-3분
**독립 실행**: 가능
**테스트 방식**: 사용자 플로우 기반

#### 통합 플로우

- **플로우 1**: 완전한 일정 생명주기: 생성 → 조회 → 수정 → 삭제
- **플로우 2**: 시간 유효성 검증 후 정상 생성

#### 핵심 검증 사항

- 일정의 전체 생명주기 관리 (실제 사용자 행동 패턴)
- 폼 유효성 검사 (시작 시간 < 종료 시간)
- 수정 후 변경사항 즉시 반영
- 삭제 후 완전한 제거 확인

**독립 실행**: 가능

- "이 일정만" vs "모든 일정" 다이얼로그 처리
- 단일 수정 후 시리즈 분리 동작
- 네비게이션과 반복 일정의 통합
- 다양한 반복 유형 (daily, weekly, monthly, yearly)

## 독립적 실행 원칙

모든 시나리오는 **독립적으로 실행 가능**하도록 설계되었습니다.

### 독립성 보장 방법

1. **고유 식별자 사용**:

   ```javascript
   const timestamp = Date.now();
   const eventTitle = `E2E 테스트 일정 ${timestamp}`;
   ```

   - 각 테스트 실행마다 고유한 timestamp를 사용하여 데이터 충돌 방지

2. **자체 데이터 생성**:

   - 각 시나리오는 필요한 데이터를 직접 생성
   - 다른 시나리오의 데이터에 의존하지 않음

3. **자체 데이터 정리**:

   - 각 시나리오 완료 후 생성한 모든 데이터 삭제
   - 후처리(Postconditions) 섹션에서 정리 단계 명시

4. **서로 다른 날짜 사용 (권장)**:
   - 병렬 실행 시 날짜 충돌 방지
   - 예: 시나리오 1은 11월 5일, 시나리오 2는 11월 10일 사용

### 병렬 실행 가능성

독립적 실행 설계 덕분에 다음과 같이 병렬 실행이 가능합니다:

```bash
# Playwright에서 병렬 실행
npx playwright test --workers=4
```

**주의사항**:

- 알림 테스트는 실시간 대기가 필요하므로 병렬 실행 시 주의
- 동일한 날짜를 사용하는 시나리오는 순차 실행 권장

## 테스트 데이터 전략

### timestamp 기반 고유 식별자

모든 시나리오에서 다음 패턴을 사용합니다:

```javascript
const timestamp = Date.now();
const eventTitle = `테스트 일정 ${timestamp}`;
```

### 고정된 날짜 사용

현재 날짜에 의존하지 않고 고정된 미래 날짜를 사용합니다:

```javascript
const eventDate = '2025-11-05'; // 고정된 날짜
```

### 검색 키워드 전략

검색 시나리오에서는 고유한 검색 키워드를 사용합니다:

```javascript
const searchKeyword = `SEARCH_${timestamp}`;
```

## 실패 처리

### 공통 실패 조건

모든 시나리오에서 다음 경우 테스트가 실패합니다:

1. **API 오류**:

   - 4xx, 5xx 응답 코드
   - 네트워크 타임아웃
   - 잘못된 응답 형식

2. **UI 요소 누락**:

   - 필수 UI 요소를 찾을 수 없음
   - 타임아웃 발생

3. **데이터 불일치**:

   - 생성/수정한 데이터가 UI에 반영되지 않음
   - 삭제한 데이터가 여전히 표시됨

4. **유효성 검증 실패**:
   - 잘못된 입력이 허용됨
   - 올바른 입력이 거부됨

### 디버깅 팁

테스트 실패 시 다음을 확인하세요:

1. **서버 상태**:

   ```bash
   # 백엔드 서버가 실행 중인지 확인
   curl http://localhost:3000/api/events

   # 프론트엔드 서버가 실행 중인지 확인
   curl http://localhost:5173
   ```

2. **환경 변수**:

   ```bash
   # TEST_ENV=e2e가 설정되어 있는지 확인
   echo $TEST_ENV
   ```

3. **테스트 데이터**:

   - `src/__mocks__/response/e2e.json` 파일 확인
   - 이전 테스트의 데이터가 정리되지 않았는지 확인

4. **브라우저 콘솔**:
   - Playwright의 스크린샷 및 비디오 기능 활용
   - 브라우저 콘솔 로그 확인

## 테스트 실행 예시

### 전체 시나리오 실행

```bash
# 1. 환경 설정
TEST_ENV=e2e pnpm server &
pnpm start &

# 2. 테스트 실행 대기
sleep 5

# 3. Playwright 테스트 실행
npx playwright test
```

### 특정 시나리오만 실행

```bash
# 기본 일정 관리 시나리오만 실행
npx playwright test basic-event-management

# 반복 일정 시나리오만 실행
npx playwright test recurring-event-management
```

### 헤드리스 모드 해제 (디버깅용)

```bash
# 브라우저 UI를 보면서 실행
npx playwright test --headed

# 느린 실행 (각 단계 확인)
npx playwright test --headed --slow-mo=1000
```

### 시나리오 추가 시

1. **새 파일 생성**:

   - 파일명: `0X-feature-name.md`
   - 번호는 순서대로 증가

2. **필수 섹션 포함**:

   - 시나리오 개요
   - 사용자 스토리
   - 전제조건
   - 테스트 데이터
   - 테스트 단계
   - 후처리
   - 실패 조건
   - 주의사항

3. **독립성 보장**:
   - 고유 식별자 사용
   - 자체 데이터 생성 및 정리

### 시나리오 수정 시

1. **변경 사항 문서화**:

   - 변경 이유 기록
   - 영향받는 다른 시나리오 확인

2. **테스트 검증**:
   - 수정된 시나리오 단독 실행
