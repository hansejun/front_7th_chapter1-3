# E2E 테스트 시나리오: 검색 및 네비게이션

## 시나리오 개요

일정 검색 기능과 캘린더 네비게이션(주간/월간 보기, 이전/다음 이동) 기능을 검증합니다.

**우선순위**: High
**예상 실행 시간**: 3-4분
**독립 실행**: 가능 (자체 데이터 생성 및 정리)

---

## 시나리오 1: 일정 검색 기능

### 사용자 스토리

사용자가 검색어를 입력하여 제목, 설명, 위치로 일정을 필터링할 수 있어야 합니다.

### 전제조건

- 애플리케이션이 http://localhost:5173 에서 실행 중
- 백엔드 서버가 http://localhost:3000 에서 실행 중
- TEST_ENV=e2e 환경 변수 설정됨
- 브라우저가 깨끗한 상태

### 테스트 데이터

```javascript
const timestamp = Date.now();
const searchKeyword = `SEARCH_${timestamp}`;

// 제목에 검색어가 포함된 일정
const event1 = {
  title: `${searchKeyword} 팀 회의`,
  date: '2025-11-15',
  startTime: '10:00',
  endTime: '11:00',
  description: '주간 팀 회의입니다',
  location: '회의실 A',
  category: '업무',
};

// 설명에 검색어가 포함된 일정
const event2 = {
  title: '프로젝트 리뷰',
  date: '2025-11-16',
  startTime: '14:00',
  endTime: '15:00',
  description: `${searchKeyword} 프로젝트 진행 상황 리뷰`,
  location: '회의실 B',
  category: '업무',
};

// 위치에 검색어가 포함된 일정
const event3 = {
  title: '점심 약속',
  date: '2025-11-17',
  startTime: '12:00',
  endTime: '13:00',
  description: '동료와 점심 식사',
  location: `${searchKeyword} 레스토랑`,
  category: '개인',
};

// 검색어가 포함되지 않은 일정
const event4 = {
  title: '개인 작업',
  date: '2025-11-18',
  startTime: '16:00',
  endTime: '17:00',
  description: '개인 업무 처리',
  location: '사무실',
  category: '개인',
};
```

### 테스트 단계

#### 1. 테스트용 일정 생성

**액션**:

1. event1, event2, event3, event4를 순서대로 생성
2. 각 일정 생성 후 일정 목록에 표시되는지 확인

**예상 결과**:

- 4개의 일정이 모두 생성됨
- 일정 목록에 4개의 일정이 표시됨

#### 2. 검색 필드 확인

**액션**:

1. 오른쪽 상단의 "일정 검색" 필드 확인

**예상 결과**:

- 검색 입력 필드가 표시됨
- 플레이스홀더: "검색어를 입력하세요"

#### 3. 검색어로 필터링

**액션**:

1. 검색 필드에 `searchKeyword` 입력

**예상 결과**:

- 일정 목록이 실시간으로 필터링됨
- 3개의 일정만 표시됨 (event1, event2, event3)
- event4는 표시되지 않음 (검색어가 포함되지 않음)
- 표시된 일정들:
  - `${searchKeyword} 팀 회의` (제목 일치)
  - `프로젝트 리뷰` (설명 일치)
  - `점심 약속` (위치 일치)

#### 4. 대소문자 구분 없는 검색 (선택사항)

**액션**:

1. 검색 필드를 지우고 소문자로 `searchKeyword.toLowerCase()` 입력

**예상 결과**:

- 대소문자를 구분하지 않고 동일한 결과가 표시됨 (구현에 따라 다름)
- 또는 대소문자를 구분하여 결과가 다를 수 있음

#### 5. 부분 검색

**액션**:

1. 검색 필드를 지우고 `searchKeyword`의 일부분만 입력

**예상 결과**:

- 부분 일치도 검색됨 (구현에 따라 다름)

#### 6. 검색 초기화

**액션**:

1. 검색 필드의 내용을 모두 지움

**예상 결과**:

- 일정 목록이 전체 일정을 표시함
- 4개의 일정이 모두 다시 표시됨

## 시나리오 2: 월간/주간 보기 전환

### 사용자 스토리

사용자가 캘린더를 월간 보기와 주간 보기로 전환할 수 있어야 합니다.

### 전제조건

- 시나리오 1에서 생성한 일정들이 존재함

### 테스트 단계

#### 1. 초기 보기 확인

**액션**:

1. 캘린더 중앙 영역의 뷰 타입 선택 드롭다운 확인

**예상 결과**:

- 기본값: "Month" (월간 보기)
- 드롭다운 옵션: "Month", "Week"

#### 2. 월간 보기 확인

**액션**:

1. 월간 보기에서 캘린더 구조 확인

**예상 결과**:

- 현재 월 제목 표시: "2025년 11월" (현재 날짜 기준)
- 7개 열 (일-토)
- 해당 월의 모든 날짜가 표시됨
- 11월 15일, 16일, 17일, 18일에 생성한 일정들이 표시됨

#### 3. 주간 보기로 전환

**액션**:

1. 뷰 타입 선택 드롭다운 클릭
2. "Week" 옵션 선택

**예상 결과**:

- 캘린더가 주간 보기로 전환됨
- 현재 주의 날짜들만 표시됨
- 주 제목 표시: "2025년 11월 X주차" 또는 유사한 형식
- 7개 열 (일-토)
- 해당 주에 포함된 일정들만 표시됨

#### 4. 월간 보기로 다시 전환

**액션**:

1. 뷰 타입 선택 드롭다운 클릭
2. "Month" 옵션 선택

**예상 결과**:

- 캘린더가 월간 보기로 다시 전환됨
- 전체 월이 표시됨

## 시나리오 3: 캘린더 네비게이션 (이전/다음)

### 사용자 스토리

사용자가 이전/다음 버튼을 사용하여 월 또는 주를 이동할 수 있어야 합니다.

### 전제조건

- 시나리오 1에서 생성한 일정들이 존재함
- 월간 보기 상태

### 테스트 단계

#### 1. 월간 보기에서 다음 달로 이동

**액션**:

1. 월간 보기 확인 (2025년 11월)
2. "Next" 버튼 클릭

**예상 결과**:

- 캘린더가 12월로 전환됨
- 제목이 "2025년 12월"로 변경됨
- 12월의 날짜들이 표시됨
- 11월 일정들은 표시되지 않음

#### 2. 이전 달로 돌아가기

**액션**:

1. "Previous" 버튼 클릭

**예상 결과**:

- 캘린더가 11월로 돌아옴
- 제목이 "2025년 11월"로 변경됨
- 생성한 일정들(11/15, 11/16, 11/17, 11/18)이 다시 표시됨

#### 3. 주간 보기로 전환 후 네비게이션

**액션**:

1. 뷰 타입을 "Week"로 변경
2. "Next" 버튼 클릭
3. "Next" 버튼을 여러 번 클릭하여 몇 주 앞으로 이동
4. "Previous" 버튼을 클릭하여 이전 주로 돌아가기

**예상 결과**:

- "Next" 클릭 시 다음 주로 이동
- "Previous" 클릭 시 이전 주로 이동
- 주 제목이 올바르게 업데이트됨
- 해당 주에 포함된 일정들만 표시됨

#### 4. 여러 달 이동 후 현재 월 확인

**액션**:

1. 월간 보기로 전환
2. "Next" 버튼을 여러 번 클릭하여 미래로 이동
3. "Previous" 버튼을 클릭하여 원래 월(11월)로 돌아오기

**예상 결과**:

- 네비게이션이 정상적으로 작동함
- 원래 월로 돌아왔을 때 생성한 일정들이 여전히 표시됨

## 시나리오 4: 날짜 클릭으로 일정 폼 채우기 (선택사항)

### 사용자 스토리

사용자가 캘린더의 특정 날짜를 클릭하면 일정 생성 폼의 날짜 필드가 자동으로 채워져야 합니다.

### 전제조건

- 캘린더가 월간 보기 상태

### 테스트 단계

#### 1. 빈 날짜 셀 클릭

**액션**:

1. 캘린더에서 일정이 없는 날짜(예: 11월 20일)의 날짜 숫자 클릭

**예상 결과**:

- 왼쪽 일정 추가 폼의 "날짜" 필드가 클릭한 날짜로 자동 채워짐
- 날짜 필드 값: 2025-11-20
- 다른 필드는 비어있음
- 사용자가 제목, 시간 등을 입력하여 해당 날짜에 일정을 빠르게 생성할 수 있음

#### 2. 일정이 있는 날짜 셀 클릭

**액션**:

1. 캘린더에서 일정이 있는 날짜(예: 11월 15일)의 날짜 숫자 클릭 (일정 버튼이 아닌 날짜 숫자)

**예상 결과**:

- 일정 추가 폼의 "날짜" 필드가 클릭한 날짜로 자동 채워짐
- 날짜 필드 값: 2025-11-15
- 기존 일정이 편집 모드로 전환되지 않음 (날짜만 채워짐)

## 시나리오 5: 검색과 네비게이션 통합

### 사용자 스토리

사용자가 검색 필터를 적용한 상태에서 캘린더 네비게이션을 사용할 수 있어야 합니다.

### 전제조건

- 시나리오 1에서 생성한 일정들이 존재함

### 테스트 단계

#### 1. 검색 적용 후 다른 달로 이동

**액션**:

1. 검색 필드에 `searchKeyword` 입력 (3개 일정 필터링됨)
2. "Next" 버튼을 클릭하여 12월로 이동

**예상 결과**:

- 캘린더가 12월로 전환됨
- 검색 필터는 여전히 유지됨
- 일정 목록은 여전히 필터링된 3개 일정만 표시 (날짜와 무관하게)
- 또는 구현에 따라 검색 결과가 현재 보기와 무관할 수 있음

#### 2. 검색 초기화 후 네비게이션

**액션**:

1. 검색 필드를 지워서 필터 해제
2. 11월로 돌아가기 ("Previous" 버튼)

**예상 결과**:

- 모든 일정이 다시 표시됨
- 캘린더가 11월을 표시함

## 정리: 생성한 모든 일정 삭제

### 테스트 단계

**액션**:

1. 시나리오 1에서 생성한 4개의 일정 삭제:
   - `${searchKeyword} 팀 회의`
   - `프로젝트 리뷰`
   - `점심 약속`
   - `개인 작업`
2. 각 일정의 "Delete event" 버튼 클릭하여 삭제

**예상 결과**:

- 모든 테스트 일정이 삭제됨
- 일정 목록과 캘린더가 깨끗함

## 후처리 (Postconditions)

테스트가 완료된 후 다음을 확인합니다:

1. **데이터 정리 확인**:

   - 테스트 중 생성한 모든 일정이 삭제되었는지 확인
   - timestamp를 포함한 제목으로 검색하여 남은 일정이 없는지 검증

2. **UI 상태 초기화**:

   - 검색 필드가 비어있는지 확인
   - 캘린더가 현재 월을 표시하는지 확인
   - 월간 보기로 되어있는지 확인 (기본값)

3. **다른 테스트 영향 없음**:
   - E2E 테스트 데이터에 기존 일정들이 그대로 있는지 확인

---

## 실패 조건

다음 경우 테스트가 실패합니다:

1. 검색어 입력 시 일정이 필터링되지 않음
2. 검색어와 관련 없는 일정이 표시됨
3. 월간/주간 보기 전환이 작동하지 않음
4. 이전/다음 네비게이션이 작동하지 않음
5. 날짜 클릭 시 폼이 채워지지 않음
6. 검색 상태가 네비게이션 후 의도치 않게 초기화됨 (또는 유지되지 않음)
7. UI 요소를 찾을 수 없음

---

## 주의사항

1. **독립성 보장**:

   - 고유한 timestamp를 사용하여 데이터 충돌 방지
   - 시나리오 완료 후 생성한 모든 일정 삭제
   - 다른 테스트의 일정이 검색 결과에 포함되지 않도록 고유 검색어 사용

2. **검색 동작**:

   - 검색이 실시간으로 작동하는지 확인 (debounce 고려)
   - 대소문자 구분 여부 확인
   - 부분 일치 vs 완전 일치 확인

3. **네비게이션 상태**:

   - 캘린더 네비게이션 후 선택된 보기 타입이 유지되는지 확인
   - 네비게이션 후 일정 데이터가 올바르게 로드되는지 확인

4. **병렬 실행**:

   - 서로 다른 검색 키워드를 사용하면 병렬 실행 가능
   - 서로 다른 날짜 범위를 사용하여 충돌 방지

5. **현재 날짜 의존성**:
   - 테스트가 현재 날짜에 의존하지 않도록 고정된 날짜 사용
   - 네비게이션 테스트 시 상대적 이동보다 절대적 날짜 확인
