# E2E 테스트 시나리오: 반복 일정 관리

## 시나리오 개요

반복 일정의 생성, 수정, 삭제 워크플로우를 검증합니다. 특히 "이 일정만" vs "모든 일정" 옵션을 중점적으로 테스트합니다.

**우선순위**: Critical
**예상 실행 시간**: 5-7분
**독립 실행**: 가능 (자체 데이터 생성 및 정리)

---

## 시나리오 1: 주간 반복 일정 생성

### 사용자 스토리

사용자가 매주 반복되는 일정을 생성하고, 캘린더에서 여러 날짜에 반복 일정이 표시되는 것을 확인할 수 있어야 합니다.

### 전제조건

- 애플리케이션이 http://localhost:5173 에서 실행 중
- 백엔드 서버가 http://localhost:3000 에서 실행 중
- TEST_ENV=e2e 환경 변수 설정됨
- 브라우저가 깨끗한 상태

### 테스트 데이터

```javascript
const timestamp = Date.now();
const recurringTitle = `주간 회의 ${timestamp}`;
const startDate = '2025-11-10'; // 월요일
const endDate = '2025-12-08'; // 4주 후
const startTime = '10:00';
const endTime = '11:00';
const description = `매주 월요일 팀 회의 (${timestamp})`;
const location = '회의실 A';
const category = '업무';
const repeatType = '매주'; // weekly
const repeatInterval = 1;
const notification = '10분 전';
```

### 테스트 단계

#### 1. 반복 일정 폼 작성

**액션**:

1. "제목" 필드에 `recurringTitle` 입력
2. "날짜" 필드에 `startDate` 입력
3. "시작 시간" 필드에 `startTime` 입력
4. "종료 시간" 필드에 `endTime` 입력
5. "설명" 필드에 `description` 입력
6. "위치" 필드에 `location` 입력
7. "카테고리" 드롭다운에서 `category` 선택
8. "반복 일정" 체크박스 클릭
9. "반복 유형" 드롭다운에서 `repeatType` 선택
10. "반복 간격" 필드에 `repeatInterval` 입력 (기본값 1 확인)
11. "반복 종료일" 필드에 `endDate` 입력
12. "알림 설정" 드롭다운에서 `notification` 선택

**예상 결과**:

- "반복 일정" 체크박스를 클릭하면 반복 옵션이 표시됨
- 반복 유형 옵션: 매일, 매주, 매월, 매년
- 모든 입력 필드에 값이 올바르게 입력됨

#### 2. 반복 일정 생성

**액션**:

- "일정 추가" 버튼 클릭

**예상 결과**:

- POST /api/events-list 요청이 전송됨 (여러 일정을 한 번에 생성)
- 응답 상태 코드: 201
- 폼이 초기화됨
- 생성된 모든 반복 일정에 동일한 `repeat.id` (repeatId) 부여됨

#### 3. 캘린더에서 반복 일정 확인

**액션**:

1. 월간 보기에서 11월 확인
2. 필요시 다음 달(12월)로 이동하여 확인

**예상 결과**:

- 11월 10일, 17일, 24일에 일정이 표시됨
- 12월 1일, 8일에도 일정이 표시됨
- 총 5개의 반복 일정이 생성됨
- 각 일정 옆에 반복 아이콘이 표시됨

#### 4. 일정 목록에서 반복 정보 확인

**액션**:

1. 오른쪽 일정 목록에서 생성한 반복 일정들 확인

**예상 결과**:

- 5개의 일정이 모두 목록에 표시됨
- 각 일정에 다음 정보가 표시됨:
  - 제목: `recurringTitle`
  - 날짜: 각각 2025-11-10, 11-17, 11-24, 12-01, 12-08
  - 시간: 10:00 - 11:00
  - 설명: `description`
  - 위치: `location`
  - 카테고리: 업무
  - **반복: 1주마다 (종료: 2025-12-08)**
  - 알림: 10분 전
- 각 일정에 반복 아이콘이 표시됨

## 시나리오 2: 반복 일정 단일 항목 수정

### 사용자 스토리

사용자가 반복 일정 시리즈 중 하나의 일정만 선택적으로 수정할 수 있어야 합니다.

### 전제조건

- 시나리오 1에서 생성한 주간 반복 일정이 존재함

### 테스트 데이터

```javascript
const singleEditTitle = `${recurringTitle} (11/17만 수정)`;
const singleEditLocation = '회의실 B';
```

### 테스트 단계

#### 1. 단일 일정 수정 시작

**액션**:

1. 일정 목록에서 11월 17일 일정의 "Edit event" 버튼 클릭

**예상 결과**:

- **"반복 일정 수정" 다이얼로그**가 표시됨
- 다이얼로그 내용: "해당 일정만 수정하시겠어요?"
- 버튼: "취소", "아니오", "예"

#### 2. "이 일정만" 옵션 선택

**액션**:

1. "예" 버튼 클릭 (해당 일정만 수정)

**예상 결과**:

- 다이얼로그가 닫힘
- 일정 추가 폼에 11월 17일 일정의 데이터가 채워짐
- "반복 일정" 체크박스가 해제되거나 단일 수정 모드로 전환됨

#### 3. 일정 정보 수정

**액션**:

1. "제목" 필드를 `singleEditTitle`로 수정
2. "위치" 필드를 `singleEditLocation`로 수정
3. "일정 수정" 버튼 클릭

**예상 결과**:

- PUT /api/events/:id 요청이 전송됨 (단일 일정만)
- 응답 상태 코드: 200

#### 4. 수정 결과 확인

**액션**:

1. 일정 목록에서 모든 반복 일정 확인

**예상 결과**:

- 11월 17일 일정만 제목과 위치가 변경됨
  - 제목: `singleEditTitle`
  - 위치: `singleEditLocation`
- 다른 날짜(11/10, 11/24, 12/01, 12/08)의 일정은 변경되지 않음
  - 제목: `recurringTitle` (원래 제목)
  - 위치: `location` (원래 위치)

## 시나리오 3: 반복 일정 전체 시리즈 수정

### 사용자 스토리

사용자가 반복 일정 시리즈의 모든 일정을 한 번에 수정할 수 있어야 합니다.

### 전제조건

- 시나리오 2에서 부분 수정한 반복 일정이 존재함

### 테스트 데이터

```javascript
const seriesEditDescription = `${description} - 전체 시리즈 수정됨`;
const seriesEditCategory = '개인';
const seriesEditTime = '11:00';
const seriesEditEndTime = '12:00';
```

### 테스트 단계

#### 1. 전체 시리즈 수정 시작

**액션**:

1. 일정 목록에서 수정되지 않은 일정(예: 11월 10일)의 "Edit event" 버튼 클릭

**예상 결과**:

- "반복 일정 수정" 다이얼로그가 표시됨

#### 2. "모든 일정" 옵션 선택

**액션**:

1. "아니오" 버튼 클릭 (모든 반복 일정 수정)

**예상 결과**:

- 다이얼로그가 닫힘
- 일정 추가 폼에 반복 일정의 기본 정보가 채워짐
- "반복 일정" 체크박스가 선택된 상태로 유지됨

#### 3. 시리즈 전체 정보 수정

**액션**:

1. "설명" 필드를 `seriesEditDescription`로 수정
2. "카테고리"를 `seriesEditCategory`로 변경
3. "시작 시간"을 `seriesEditTime`로 수정
4. "종료 시간"을 `seriesEditEndTime`로 수정
5. "일정 수정" 버튼 클릭

**예상 결과**:

- repeatId가 있는 경우: PUT /api/recurring-events/:repeatId 요청이 전송됨
- repeatId가 없는 경우: 여러 개의 PUT /api/events/:id 요청이 전송됨
- 응답 상태 코드: 200

#### 4. 전체 수정 결과 확인

**액션**:

1. 일정 목록에서 모든 반복 일정 확인

**예상 결과**:

- **모든 반복 일정**이 수정됨 (11/10, 11/17, 11/24, 12/01, 12/08)
  - 설명: `seriesEditDescription`
  - 카테고리: 개인
  - 시간: 11:00 - 12:00
- 11월 17일 일정의 개별 수정 사항도 유지됨:
  - 제목: `singleEditTitle` (이전에 수정한 제목)
  - 위치: `singleEditLocation` (이전에 수정한 위치)
- 또는 개별 수정 사항이 덮어쓰기될 수 있음 (구현에 따라 다름 - 문서화 필요)

## 시나리오 6: 다양한 반복 유형 테스트

### 사용자 스토리

사용자가 일일, 월간, 연간 등 다양한 반복 유형의 일정을 생성할 수 있어야 합니다.

### 전제조건

- 애플리케이션이 정상 실행 중

### 테스트 단계

#### 1. 매일 반복 일정 생성

**액션**:

1. 다음 정보로 일정 생성:
   - 제목: `매일 스탠드업 ${timestamp}`
   - 날짜: 2025-11-03
   - 시간: 09:00 - 09:15
   - 반복 유형: 매일
   - 반복 간격: 1
   - 종료일: 2025-11-07
2. "일정 추가" 버튼 클릭

**예상 결과**:

- 5일간(11/03 ~ 11/07) 매일 일정이 생성됨
- 총 5개의 일정이 생성됨

#### 2. 매월 반복 일정 생성

**액션**:

1. 다음 정보로 일정 생성:
   - 제목: `월간 보고 ${timestamp}`
   - 날짜: 2025-11-01
   - 시간: 15:00 - 16:00
   - 반복 유형: 매월
   - 반복 간격: 1
   - 종료일: 2025-12-31
2. "일정 추가" 버튼 클릭

**예상 결과**:

- 2개월간(11월, 12월) 매월 1일에 일정이 생성됨
- 총 2개의 일정이 생성됨
- 각 일정 날짜: 2025-11-01, 2025-12-01

#### 3. 매년 반복 일정 생성

**액션**:

1. 다음 정보로 일정 생성:
   - 제목: `생일 축하 ${timestamp}`
   - 날짜: 2025-11-15
   - 시간: 00:00 - 23:59
   - 반복 유형: 매년
   - 반복 간격: 1
   - 종료일: 2025-12-30 (최대 종료일)
2. "일정 추가" 버튼 클릭

**예상 결과**:

- 1개의 일정만 생성됨 (종료일이 1년 미만이므로)
- 날짜: 2025-11-15

#### 4. 정리 - 생성한 모든 반복 일정 삭제

**액션**:

1. 매일 반복 일정 중 하나를 선택하여 "Delete event" 클릭
2. "아니오" 버튼 클릭 (모든 일정 삭제)
3. 매월 반복 일정에 대해 동일 작업 반복
4. 매년 반복 일정에 대해 동일 작업 반복

**예상 결과**:

- 생성한 모든 테스트 일정이 삭제됨

## 후처리 (Postconditions)

테스트가 완료된 후 다음을 확인합니다:

1. **데이터 정리 확인**:

   - 테스트 중 생성한 모든 반복 일정이 삭제되었는지 확인
   - timestamp를 포함한 제목으로 검색하여 남은 일정이 없는지 검증

2. **상태 초기화**:

   - 폼이 초기 상태로 돌아갔는지 확인
   - "반복 일정" 체크박스가 해제되었는지 확인

3. **다른 테스트 영향 없음**:
   - E2E 테스트 데이터에 기존 일정들이 그대로 있는지 확인

---

## 실패 조건

다음 경우 테스트가 실패합니다:

1. 반복 일정이 예상한 날짜에 생성되지 않음
2. "이 일정만" 옵션 선택 시 다른 일정이 영향받음
3. "모든 일정" 옵션 선택 시 일부 일정이 수정/삭제되지 않음
4. 반복 일정 다이얼로그가 표시되지 않음
5. repeatId가 올바르게 부여되지 않음
6. API 요청이 실패함
7. UI 요소를 찾을 수 없음

---

## 주의사항

1. **독립성 보장**:

   - 고유한 timestamp를 사용하여 데이터 충돌 방지
   - 각 시나리오 완료 후 생성한 모든 반복 일정 삭제

2. **반복 일정 범위**:

   - 테스트를 위해 짧은 기간(4-5주)으로 제한
   - 너무 많은 일정 생성 방지

3. **다이얼로그 처리**:
