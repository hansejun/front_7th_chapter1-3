# E2E 테스트 시나리오: 일정 겹침 처리 및 알림 시스템

## 시나리오 개요

일정 시간 겹침 감지 및 경고, 그리고 알림 시스템의 동작을 검증합니다.

**우선순위**: High
**예상 실행 시간**: 4-5분
**독립 실행**: 가능 (자체 데이터 생성 및 정리)

---

## 시나리오 1: 일정 겹침 감지 및 경고

### 사용자 스토리

사용자가 기존 일정과 시간이 겹치는 새로운 일정을 생성하려고 할 때, 시스템이 겹침을 감지하고 경고 메시지를 표시해야 합니다. 사용자는 경고를 확인한 후 겹치는 일정을 생성할지 취소할지 선택할 수 있어야 합니다.

### 전제조건

- 애플리케이션이 http://localhost:5173 에서 실행 중
- 백엔드 서버가 http://localhost:3000 에서 실행 중
- TEST_ENV=e2e 환경 변수 설정됨
- 브라우저가 깨끗한 상태

### 테스트 데이터

```javascript
const timestamp = Date.now();
const baseEventTitle = `기본 일정 ${timestamp}`;
const overlappingEventTitle = `겹치는 일정 ${timestamp}`;
const eventDate = '2025-11-12';

// 기본 일정: 14:00 - 16:00
const baseStartTime = '14:00';
const baseEndTime = '16:00';

// 겹치는 일정: 15:00 - 17:00 (1시간 겹침)
const overlapStartTime = '15:00';
const overlapEndTime = '17:00';
```

### 테스트 단계

#### 1. 기본 일정 생성

**액션**:

1. 다음 정보로 첫 번째 일정 생성:
   - 제목: `baseEventTitle`
   - 날짜: `eventDate` (2025-11-12)
   - 시작 시간: `baseStartTime` (14:00)
   - 종료 시간: `baseEndTime` (16:00)
   - 카테고리: 업무
2. "일정 추가" 버튼 클릭

**예상 결과**:

- 일정이 정상적으로 생성됨
- 캘린더와 일정 목록에 표시됨

#### 2. 겹치는 시간으로 두 번째 일정 생성 시도

**액션**:

1. 다음 정보로 두 번째 일정 생성:
   - 제목: `overlappingEventTitle`
   - 날짜: `eventDate` (2025-11-12) - 동일한 날짜
   - 시작 시간: `overlapStartTime` (15:00)
   - 종료 시간: `overlapEndTime` (17:00)
   - 카테고리: 개인
2. "일정 추가" 버튼 클릭

**예상 결과**:

- **일정 겹침 경고 다이얼로그**가 표시됨
- 다이얼로그 제목: "일정 겹침 경고" 또는 유사한 메시지
- 다이얼로그 내용:
  - 겹치는 일정 정보 표시
  - "다음 일정과 겹칩니다:" 등의 메시지
  - 기존 일정 정보: `baseEventTitle`, 14:00 - 16:00
- 버튼: "취소", "계속 진행" 또는 유사한 옵션

#### 3. 겹침 경고 취소

**액션**:

1. "취소" 버튼 클릭

**예상 결과**:

- 다이얼로그가 닫힘
- 겹치는 일정이 생성되지 않음
- POST /api/events 요청이 전송되지 않음
- 폼에 입력한 데이터가 유지됨 (사용자가 시간을 수정할 수 있도록)

#### 4. 겹침 무시하고 일정 생성

**액션**:

1. 다시 "일정 추가" 버튼 클릭 (폼 데이터가 유지되어 있음)
2. 겹침 경고 다이얼로그에서 "계속 진행" 버튼 클릭

**예상 결과**:

- 다이얼로그가 닫힘
- 겹치는 일정이 생성됨
- POST /api/events 요청이 전송됨
- 응답 상태 코드: 201
- 폼이 초기화됨

#### 5. 두 일정 모두 표시 확인

**액션**:

1. 캘린더에서 11월 12일 확인
2. 일정 목록 확인

**예상 결과**:

- 11월 12일에 2개의 일정이 모두 표시됨
  - 일정 1: `baseEventTitle`, 14:00 - 16:00
  - 일정 2: `overlappingEventTitle`, 15:00 - 17:00
- 일정 목록에도 2개의 일정이 모두 표시됨

## 시나리오 2: 다양한 겹침 패턴 테스트

### 사용자 스토리

다양한 시간 겹침 패턴에 대해 시스템이 올바르게 감지할 수 있어야 합니다.

### 전제조건

- 시나리오 1에서 생성한 일정들이 존재함
- 기본 일정: 2025-11-12, 14:00 - 16:00

### 테스트 단계

#### 1. 완전히 포함되는 일정 (14:30 - 15:30)

**액션**:

1. 다음 정보로 일정 생성 시도:
   - 제목: `완전 포함 ${timestamp}`
   - 날짜: 2025-11-12
   - 시작 시간: 14:30
   - 종료 시간: 15:30
2. "일정 추가" 버튼 클릭

**예상 결과**:

- 겹침 경고 다이얼로그가 표시됨
- 기존 일정(`baseEventTitle`)과 겹친다고 표시됨

#### 2. 시작 시간이 겹치는 일정 (13:00 - 14:30)

**액션**:

1. 폼을 다음으로 수정:
   - 제목: `시작 겹침 ${timestamp}`
   - 시작 시간: 13:00
   - 종료 시간: 14:30
2. "일정 추가" 버튼 클릭

**예상 결과**:

- 겹침 경고 다이얼로그가 표시됨
- 기존 일정과 겹친다고 표시됨

#### 3. 겹치지 않는 시간 (16:00 - 17:00)

**액션**:

1. 폼을 다음으로 수정:
   - 제목: `겹치지 않음 ${timestamp}`
   - 시작 시간: 16:00 (기본 일정 종료 시간과 동일)
   - 종료 시간: 17:00
2. "일정 추가" 버튼 클릭

**예상 결과**:

- 겹침 경고 다이얼로그가 **표시되지 않음** (종료 시간과 시작 시간이 같으면 겹치지 않음)
- 또는 구현에 따라 경고가 표시될 수 있음 (경계 케이스)
- 일정이 정상적으로 생성됨

#### 4. 다른 날짜 (16:00 - 17:00, 다른 날)

**액션**:

1. 폼을 다음으로 수정:
   - 제목: `다른 날 ${timestamp}`
   - 날짜: 2025-11-13 (다른 날짜)
   - 시작 시간: 14:00
   - 종료 시간: 16:00
2. "일정 추가" 버튼 클릭

**예상 결과**:

- 겹침 경고 다이얼로그가 표시되지 않음
- 일정이 정상적으로 생성됨 (날짜가 다르므로 겹치지 않음)

## 시나리오 3: 알림 시스템 기본 동작

### 사용자 스토리

사용자가 설정한 시간에 일정 알림을 받을 수 있어야 합니다.

### 전제조건

- 애플리케이션이 실행 중
- 브라우저 시간이 정확함

### 테스트 데이터

```javascript
const notificationTimestamp = Date.now();
const notificationEventTitle = `알림 테스트 ${notificationTimestamp}`;

// 현재 시간 기준 2분 후 일정 생성
const now = new Date();
const eventStart = new Date(now.getTime() + 2 * 60000); // 2분 후
const eventEnd = new Date(now.getTime() + 3 * 60000); // 3분 후

const eventDate = eventStart.toISOString().split('T')[0]; // YYYY-MM-DD
const eventStartTime = eventStart.toTimeString().substring(0, 5); // HH:MM
const eventEndTime = eventEnd.toTimeString().substring(0, 5); // HH:MM
```

### 테스트 단계

#### 1. 임박한 일정 생성

**액션**:

1. 다음 정보로 일정 생성:
   - 제목: `notificationEventTitle`
   - 날짜: `eventDate` (오늘)
   - 시작 시간: `eventStartTime` (현재 시간 + 2분)
   - 종료 시간: `eventEndTime` (현재 시간 + 3분)
   - 알림 설정: **1분 전**
2. "일정 추가" 버튼 클릭

**예상 결과**:

- 일정이 정상적으로 생성됨

#### 2. 알림 대기 및 확인

**액션**:

1. 약 1분 대기 (일정 시작 1분 전이 되면 알림 표시 예상)
2. 페이지를 활성 상태로 유지
3. 알림 영역 또는 브라우저 알림 확인

**예상 결과**:

- 일정 시작 1분 전에 알림이 표시됨
- 알림 내용:
  - 일정 제목: `notificationEventTitle`
  - 일정 시간 정보
  - "곧 시작됩니다" 등의 메시지
- 알림이 화면에 표시되거나 브라우저 알림으로 표시됨
- 동일한 일정에 대한 중복 알림이 표시되지 않음

**주의**: 이 테스트는 실시간 대기가 필요하므로 자동화 테스트에서는 시간을 조작하거나 Mock을 사용해야 할 수 있습니다.

#### 3. 알림 중복 방지 확인

**액션**:

1. 페이지를 새로고침하거나 다른 탭으로 갔다가 돌아오기
2. 알림 영역 확인

**예상 결과**:

- 이미 표시된 알림이 다시 표시되지 않음
- useNotifications 훅에서 notifiedEvents 상태로 중복 방지

## 시나리오 4: 다양한 알림 시간 설정

### 사용자 스토리

사용자가 다양한 알림 시간 옵션을 선택할 수 있어야 합니다.

### 전제조건

- 애플리케이션이 실행 중

### 테스트 단계

#### 1. 알림 시간 옵션 확인

**액션**:

1. "알림 설정" 드롭다운 클릭

**예상 결과**:

- 다음 옵션들이 표시됨:
  - 1분 전
  - 10분 전
  - 1시간 전
  - 1일 전
  - (기타 애플리케이션에서 제공하는 옵션)

#### 2. 각 알림 시간 설정으로 일정 생성

**액션**:

1. "1분 전" 알림으로 일정 생성
2. "10분 전" 알림으로 다른 일정 생성
3. "1시간 전" 알림으로 또 다른 일정 생성

**예상 결과**:

- 각 일정이 선택한 알림 시간과 함께 생성됨
- 일정 목록에서 각 일정의 알림 설정이 올바르게 표시됨
  - "알림: 1분 전"
  - "알림: 10분 전"
  - "알림: 1시간 전"

---

## 정리: 생성한 모든 일정 삭제

### 테스트 단계

**액션**:

1. 시나리오 1-4에서 생성한 모든 일정 삭제:
   - `baseEventTitle`
   - `overlappingEventTitle`
   - `완전 포함`, `시작 겹침`, `겹치지 않음`, `다른 날` (생성된 경우)
   - `notificationEventTitle`
   - 알림 시간 테스트로 생성한 일정들
2. 각 일정의 "Delete event" 버튼 클릭하여 삭제

**예상 결과**:

- 모든 테스트 일정이 삭제됨
- 일정 목록과 캘린더가 깨끗함

---

## 후처리 (Postconditions)

테스트가 완료된 후 다음을 확인합니다:

1. **데이터 정리 확인**:

   - 테스트 중 생성한 모든 일정이 삭제되었는지 확인
   - timestamp를 포함한 제목으로 검색하여 남은 일정이 없는지 검증

2. **알림 상태 초기화**:

   - 표시된 알림이 닫혔는지 확인
   - notifiedEvents 상태가 초기화되었는지 확인 (필요시)

3. **다른 테스트 영향 없음**:
   - E2E 테스트 데이터에 기존 일정들이 그대로 있는지 확인

---

## 실패 조건

다음 경우 테스트가 실패합니다:

1. 겹치는 일정 생성 시 경고 다이얼로그가 표시되지 않음
2. 겹치지 않는 일정에서 경고가 표시됨 (false positive)
3. 경고를 무시하고 일정 생성이 작동하지 않음
4. 알림이 설정한 시간에 표시되지 않음
5. 알림이 중복으로 표시됨
6. 알림 시간 옵션이 제대로 작동하지 않음
7. UI 요소를 찾을 수 없음

---

## 주의사항

1. **독립성 보장**:

   - 고유한 timestamp를 사용하여 데이터 충돌 방지
   - 각 시나리오 완료 후 생성한 모든 일정 삭제

2. **알림 테스트 타이밍**:

   - 실시간 알림 테스트는 시간이 소요됨
   - 자동화 테스트에서는 시간을 조작하거나 Mock 사용 권장
   - 또는 알림 로직을 유닛 테스트로 검증하고 E2E에서는 UI만 확인

3. **겹침 감지 로직**:

   - 경계 케이스 주의 (종료 시간 = 다음 일정 시작 시간)
   - 구현에 따라 동작이 다를 수 있음

4. **병렬 실행**:

   - 서로 다른 날짜를 사용하여 병렬 실행 가능
   - 알림 테스트는 실시간 대기가 필요하므로 병렬 실행 시 주의

5. **브라우저 알림 권한**:
   - 브라우저 알림을 사용하는 경우 권한 허용 필요
   - 테스트 환경에서 자동으로 권한이 허용되도록 설정
