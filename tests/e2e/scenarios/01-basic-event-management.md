# E2E 테스트 시나리오: 기본 일정 관리

## 시나리오 개요

기본적인 일정 생성, 조회, 수정, 삭제(CRUD) 워크플로우를 검증합니다.

**우선순위**: Critical
**예상 실행 시간**: 3-4분
**독립 실행**: 가능 (자체 데이터 생성 및 정리)

---

## 시나리오 1: 단일 일정 생성 및 확인

### 사용자 스토리

사용자가 새로운 일정을 생성하고 캘린더와 일정 목록에서 생성된 일정을 확인할 수 있어야 합니다.

### 전제조건

- 애플리케이션이 http://localhost:5173 에서 실행 중
- 백엔드 서버가 http://localhost:3000 에서 실행 중
- TEST_ENV=e2e 환경 변수 설정됨
- 브라우저가 깨끗한 상태 (캐시 없음)

### 테스트 데이터

독립적인 실행을 위해 고유한 식별자를 사용합니다:

```javascript
const timestamp = Date.now();
const eventTitle = `E2E 테스트 일정 ${timestamp}`;
const eventDate = '2025-11-05'; // 고정된 미래 날짜
const startTime = '14:00';
const endTime = '15:30';
const description = `자동화 테스트로 생성된 일정 (${timestamp})`;
const location = 'E2E 테스트 회의실';
const category = '업무';
const notification = '10분 전';
```

### 테스트 단계

#### 1. 애플리케이션 접속

**액션**:

- http://localhost:5173 으로 이동

**예상 결과**:

- 페이지 제목: "일정관리 앱으로 학습하는 테스트 코드"
- 왼쪽에 "일정 추가" 폼이 표시됨
- 중앙에 "일정 보기" 캘린더가 표시됨
- 오른쪽에 "일정 검색" 필드와 일정 목록이 표시됨

#### 2. 일정 폼 작성

**액션**:

1. "제목" 필드에 `eventTitle` 입력
2. "날짜" 필드에 `eventDate` 입력
3. "시작 시간" 필드에 `startTime` 입력
4. "종료 시간" 필드에 `endTime` 입력
5. "설명" 필드에 `description` 입력
6. "위치" 필드에 `location` 입력
7. "카테고리" 드롭다운에서 `category` 선택
8. "알림 설정" 드롭다운에서 `notification` 선택

**예상 결과**:

- 모든 입력 필드에 값이 올바르게 입력됨
- 폼 유효성 검사 통과 (시작 시간 < 종료 시간)
- "일정 추가" 버튼이 활성화됨

#### 3. 일정 생성

**액션**:

- "일정 추가" 버튼 클릭

**예상 결과**:

- POST /api/events 요청이 전송됨
- 응답 상태 코드: 201
- 폼이 초기화됨 (모든 필드가 비워짐)
- 성공 알림 또는 피드백 표시 (있는 경우)

#### 4. 캘린더에서 일정 확인

**액션**:

1. 월간 보기에서 11월 5일 날짜 셀 확인

**예상 결과**:

- 11월 5일 셀에 생성한 일정이 표시됨
- 일정 제목이 표시됨
- 일정을 클릭할 수 있음

#### 5. 일정 목록에서 확인

**액션**:

1. 오른쪽 일정 목록 영역 확인

**예상 결과**:

- 생성한 일정이 목록에 표시됨
- 다음 정보가 표시됨:
  - 제목: `eventTitle`
  - 날짜: 2025-11-05
  - 시간: 14:00 - 15:30
  - 설명: `description`
  - 위치: `location`
  - 카테고리: 업무
  - 알림: 10분 전
- "Edit event" 버튼과 "Delete event" 버튼이 표시됨

## 시나리오 2: 일정 수정

### 사용자 스토리

사용자가 생성한 일정의 정보를 수정할 수 있어야 합니다.

### 전제조건

- 시나리오 1에서 생성한 일정이 존재함

### 테스트 데이터

```javascript
const updatedTitle = `${eventTitle} (수정됨)`;
const updatedDescription = `${description} - 내용이 수정되었습니다`;
const updatedLocation = 'E2E 테스트 회의실 2';
const updatedCategory = '개인';
```

### 테스트 단계

#### 1. 일정 수정 모드 진입

**액션**:

1. 일정 목록에서 생성한 일정 찾기
2. "Edit event" 버튼 클릭

**예상 결과**:

- 일정 추가 폼에 기존 일정 데이터가 채워짐
- "일정 추가" 버튼이 "일정 수정" 버튼으로 변경됨

#### 2. 일정 정보 수정

**액션**:

1. "제목" 필드를 `updatedTitle`로 수정
2. "설명" 필드를 `updatedDescription`로 수정
3. "위치" 필드를 `updatedLocation`로 수정
4. "카테고리"를 `updatedCategory`로 변경

**예상 결과**:

- 모든 필드가 새로운 값으로 업데이트됨

#### 3. 수정사항 저장

**액션**:

- "일정 수정" 버튼 클릭

**예상 결과**:

- PUT /api/events/:id 요청이 전송됨
- 응답 상태 코드: 200
- 폼이 초기화됨

#### 4. 수정된 일정 확인

**액션**:

1. 일정 목록에서 수정된 일정 확인

**예상 결과**:

- 제목이 `updatedTitle`로 표시됨
- 설명이 `updatedDescription`로 표시됨
- 위치가 `updatedLocation`로 표시됨
- 카테고리가 "개인"으로 표시됨
- 날짜와 시간은 변경되지 않음

## 시나리오 3: 일정 삭제 및 정리

### 사용자 스토리

사용자가 더 이상 필요하지 않은 일정을 삭제할 수 있어야 합니다.

### 전제조건

- 시나리오 2에서 수정한 일정이 존재함

### 테스트 단계

#### 1. 일정 삭제

**액션**:

1. 일정 목록에서 수정한 일정 찾기
2. "Delete event" 버튼 클릭
3. 삭제 확인 다이얼로그가 나타나면 확인 (있는 경우)

**예상 결과**:

- DELETE /api/events/:id 요청이 전송됨
- 응답 상태 코드: 200 또는 204
- 삭제 성공 피드백 표시 (있는 경우)

#### 2. 삭제 확인

**액션**:

1. 일정 목록 확인
2. 캘린더의 11월 5일 셀 확인

**예상 결과**:

- 일정 목록에서 삭제한 일정이 사라짐
- 캘린더에서도 해당 일정이 표시되지 않음
- 다른 일정들은 영향받지 않음

---

## 시나리오 4: 시간 유효성 검증

### 사용자 스토리

사용자가 잘못된 시간 범위(종료 시간이 시작 시간보다 이른 경우)로 일정을 생성하려 할 때 적절한 오류 메시지를 받아야 합니다.

### 전제조건

- 애플리케이션이 정상 실행 중

### 테스트 데이터

```javascript
const invalidEventTitle = `유효성 검증 테스트 ${timestamp}`;
const invalidStartTime = '16:00';
const invalidEndTime = '14:00'; // 시작 시간보다 이른 종료 시간
```

### 테스트 단계

#### 1. 잘못된 시간으로 폼 작성

**액션**:

1. "제목" 필드에 `invalidEventTitle` 입력
2. "날짜" 필드에 `2025-11-06` 입력
3. "시작 시간" 필드에 `invalidStartTime` 입력
4. "종료 시간" 필드에 `invalidEndTime` 입력
5. "일정 추가" 버튼 클릭

**예상 결과**:

- 오류 메시지가 표시됨: "종료 시간은 시작 시간보다 늦어야 합니다" 또는 유사한 메시지
- 일정이 생성되지 않음
- POST /api/events 요청이 전송되지 않음
- 폼이 초기화되지 않음 (사용자가 수정할 수 있도록)

#### 2. 정상 시간으로 수정 (선택사항 - 필요시 정리용)

**액션**:

1. "종료 시간" 필드를 `17:00`으로 수정
2. "일정 추가" 버튼 클릭
3. 생성된 일정의 "Delete event" 버튼 클릭하여 정리

**예상 결과**:

- 일정이 정상적으로 생성됨
- 이후 정리됨

## 후처리 (Postconditions)

테스트가 완료된 후 다음을 확인합니다:

1. **데이터 정리 확인**:

   - 테스트 중 생성한 모든 일정이 삭제되었는지 확인
   - timestamp를 포함한 제목으로 검색하여 남은 일정이 없는지 검증

2. **상태 초기화**:

   - 폼이 초기 상태로 돌아갔는지 확인
   - 캘린더가 현재 월/주를 표시하는지 확인

3. **다른 테스트 영향 없음**:
   - E2E 테스트 데이터(e2e.json)에 기존 일정들이 그대로 있는지 확인
   - 병렬 실행 시 다른 시나리오에 영향을 주지 않았는지 확인

---

## 실패 조건

다음 경우 테스트가 실패합니다:

1. 일정 생성 후 캘린더나 목록에 표시되지 않음
2. 수정한 내용이 저장되지 않음
3. 삭제한 일정이 여전히 표시됨
4. 시간 유효성 검증이 작동하지 않음
5. API 요청이 실패함 (4xx, 5xx 오류)
6. 네트워크 오류 발생
7. UI 요소를 찾을 수 없음 (타임아웃)

---

## 주의사항

1. **독립성 보장**:

   - 고유한 timestamp를 사용하여 다른 테스트와 데이터 충돌 방지
   - 각 시나리오 실행 전 필요한 데이터만 생성
   - 각 시나리오 실행 후 생성한 데이터 정리

2. **타이밍**:

   - API 호출 후 응답 대기 시간 고려
   - UI 업데이트 후 짧은 대기 시간 필요할 수 있음
   - 네트워크 지연 고려하여 적절한 타임아웃 설정

3. **병렬 실행**:
   - 서로 다른 날짜를 사용하면 병렬 실행 가능
   - 예: 시나리오 1은 11월 5일, 시나리오 2는 11월 6일 등
